# bench/

Comparative benchmarks for ta.js against other JS technical-analysis libraries. Standalone sub-package: nothing here gets installed when consumers run `npm install ta.js`.

## Run

```sh
cd bench
npm install                    # pulls competitor libs as devDeps
npm run bench                  # terminal table
npm run bench:md               # also writes ../BENCHMARKS.md
npm run bench:json             # also writes results.json
npm run bench:coverage         # drift validator (no run; cheap)
npm run bench:coverage:write   # drift validator + writes COVERAGE.md
```

Flags (pass after `node run.js`):

- `--sizes 1000,10000,100000` — comma-separated input sizes
- `--only sma,rsi`              — restrict to specific indicators
- `--reference tulind`          — reference library for correctness diff (default: tulind; per-case `reference` overrides)
- `--md` / `--json`             — write reports
- `--quiet`                     — suppress per-row terminal output

## Method

For each (indicator, library, size):

1. **Generate** a synthetic price/OHLC series via `ta.random.prng('bench')` (seeded mulberry32). Same data passed to every library.
2. **Prepare** — reshape the raw data into the library's native input shape. Run **once per (lib, size) outside the timed loop** so we measure pure algorithm speed, not data marshaling.
3. **Sanity call** — run `compute()` once, extract a scalar series, store for the cross-library correctness diff.
4. **Time** — adaptive batch size (calibrated to ~5 ms per batch), then ≥10 samples or ≥500 ms total. Median ns/op and ops/sec reported.
5. **Compare** — every non-reference library's scalar output is aligned (trim leading non-finite, align tails) and diffed against the reference. `✓` if max abs Δ ≤ 1e-6 (rel/abs); otherwise `max Δ x.xxe-N`. The reference defaults to `tulind` but a case can declare `reference: 'technicalindicators'` (etc.) when conventions diverge — see `cases/indicators.js` ROC for an example.

```
  run.js                  # entry; orchestrates cases × sizes × libs
  harness.js              # adaptive batch timing primitive

  coverage.js             # declarative coverage SoT (one row per ta.js export)
  coverage-report.js      # drift validator + COVERAGE.md renderer
  cases.js                # legacy shim → cases/index.js (one cycle compat)
  cases/
    _libs.js              # shared lib loaders + tulindSync + id helper
    moving-averages.js    # SMA / EMA / WMA / SMMA / HULL / KAMA / VWMA + 6 solo MAs
    indicators.js         # ~30 cases (RSI, MACD, ATR, …, ALLIGATOR, ZIGZAG, …)
    oscillators.js        # AO / MOM_OSC / AC / CHAIKIN_OSC / FISHER / GATOR
    bands.js              # BBANDS / KELTNER / DON / FIBBANDS / ENVELOPE
    statistics.js         # STD / COR / RECENT_HIGH / RECENT_LOW
    chart-types.js        # HA / REN
    index.js              # aggregator: { cases, loadErrs }

  package.json            # standalone — competitors are devDeps here only
```

## Coverage

`bench/COVERAGE.md` is the single-page audit of which ta.js exports have benchmarks. Three statuses:

- **cross-lib** — at least one competitor implements the same indicator; the row records ✓ per supporting lib.
- **solo** — ta.js-only indicator (no installed competitor); benchmarked as a perf-regression tracker.
- **excluded** — scalar / utility / state-machine / async — wrong workload shape for the comparative harness.

`bench/coverage.js` is the source of truth. `bench/coverage-report.js` validates three drift conditions and exits non-zero on any failure:

1. Every ta.js export has a coverage row.
2. Every coverage row points at an actual ta.js export.
3. Every cross-lib / solo coverage row has a matching cases/<category>.js block.

Run `npm run bench:coverage` after any change to `index.js` to confirm bench wiring is in sync. Run `npm run bench:coverage:write` to additionally regenerate `COVERAGE.md`.

## Adding an indicator

1. **Implement** in ta.js (see top-level CLAUDE.md).
2. **Coverage row** — append one entry to `bench/coverage.js` with status `cross-lib` (and `libs: […]`), `solo`, or `excluded` (with `reason`).
3. **Bench case** — for `cross-lib` and `solo`, append a block to the matching `bench/cases/<category>.js` file. Each adapter has `prepare(d)` (off-clock data shaping), `compute(input)` (timed), and `extract(raw)` (scalar series for cross-lib diff). If a competitor's API drifts, omit its adapter object — the run treats absent adapters as "—".
4. **Verify** — `npm run bench:coverage` should still exit 0. `npm run bench --only <name>` should run cleanly across all configured libs.

## Adding a library

1. Add it to `bench/package.json`'s `devDependencies` and `npm install`.
2. Wire it in `bench/cases/_libs.js`: add a `try { libname = require('libname'); } catch (e) { loadErrs['libname'] = e.message; }` and re-export.
3. Add an adapter entry to each indicator's `adapters` object that the lib supports.
4. Update each affected coverage row's `libs: [...]` array.
5. If the library fails to load (e.g. native build broken on this platform), the entire library is silently skipped — the rest of the run still produces useful output.

## Caveats

- **Different formulas, not different speeds.** When two libraries diverge by a constant offset, that's usually a documented convention difference (Wilder vs Cutler, percent vs fraction, OHLC vs HLC input). The benchmark surfaces these automatically; check `bench/COVERAGE.md` notes and `CLAUDE.md` Known Issues before diagnosing as a bug.
- **Small-N is dominated by call overhead.** At 1k bars, native bindings (`tulind`) often lose to pure-JS because of JS↔C marshaling. At 100k bars the algorithmic difference dominates. Look at the scaling, not just one column.
- **Numbers are machine-specific.** Re-run on the target machine; don't quote these from another box's results.
- **Single-threaded only.** No measurement of `multi.sim` or comparable Monte-Carlo workloads.
- **TS v7 quirks.** `ts.OBV.getRequiredInputs()` returns `undefined`, causing the first `update()` call to throw. The bench's TS adapter catches the warmup throw silently — see `cases/indicators.js` OBV.
